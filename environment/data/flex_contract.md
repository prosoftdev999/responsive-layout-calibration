# Responsive flex-flow capture

The last surviving trace is from a toolbar/card-shell renderer that sits downstream of the recovered design tokens and stylesheet state. `flow_cases.ndjson` contains these renders. The trace is synthetic, but the layout semantics are a deliberately small, deterministic subset of CSS Flexbox. The point of this part of the incident is to reproduce the layout behavior, not to guess hidden constants.

Each row names either an ordinary render request or a historical render query in `source`. Recover that source exactly as for the other outputs. Use its **unrounded CSS `main` width** as the outer width of the row's root group, use its effective `char_factor_milli`, and use the source case's text scale and DPR. Historical sources therefore depend on the reconstructed session state and adopted hotfix sheets. Do not use the already-painted `main_width_milli` as the flex width.

The tree contains `group` and `leaf` nodes. Every non-root node has an `item` object describing how that node participates as a flex item in its parent. A leaf's max-content width is `label_chars * 15 * text_scale * char_factor_milli / 1000 + chrome_px`; its min-content width uses `longest_word_chars` instead of `label_chars`. `text_scale` is the source case's `text_scale_percent / 100`.

A group's border-box width includes `padding_left` and `padding_right`. Its inner main size is the assigned border-box width minus those paddings, floored at zero. Children are ordered by `(item.order, original child index)`. `flex_direction` is `row` or `row-reverse`. The root inherits the source's resolved `direction`, while each nested group inherits its parent's effective direction. Then, for every group — including the root — a non-null `direction_override` replaces that inherited direction for the group and is inherited by its descendants. `row-reverse` flips that main axis. `margin_start` and `margin_end` are logical main-axis margins; the string `auto` is an auto margin. Gaps are inserted between neighboring items on a line and are never flexible.

For this capture, intrinsic sizes of a group are defined recursively. For a child's intrinsic contribution, a pixel flex basis contributes that pixel value; an `auto` or percentage basis contributes the child's corresponding intrinsic width. Apply the child's minimum and maximum clamp to that contribution; an `auto` minimum means the child's min-content width. Fixed logical margins count toward the contribution and auto margins count as zero. A wrapping group's min-content width is its paddings plus the largest child min-content contribution. A non-wrapping group's min-content width is its paddings plus the sum of child min-content contributions and intervening gaps. A group's max-content width is its paddings plus the sum of child max-content contributions and intervening gaps.

When laying out a group, resolve each child's flex base size: `px` is literal CSS pixels, `percent` is `milli / 1000` times the group's inner main size, and `auto` is the child's max-content width. Resolve the minimum (`auto` means the child's min-content width) and optional maximum. The hypothetical size is the flex base clamped to that interval. Line collection is greedy in order-modified sequence using hypothetical outer sizes, fixed margins, and gaps. When `wrap` is false there is one line; when it is true an item begins a new line only if the current line is non-empty and adding it would exceed the group's inner main size.

Flexible lengths follow the Flexbox freeze/distribute rule on each line. To choose grow versus shrink, compare the line's inner size with the sum of every item's hypothetical size, its fixed logical margins, and all intervening gaps. Use grow factors only when that full total is smaller than the inner size; otherwise use shrink factors. The same fixed margins and gaps are subtracted when computing remaining free space, although the gaps themselves never flex. Zero-factor and already-overconstrained items become inflexible at their hypothetical size. Repeatedly distribute the remaining free space among unfrozen items; grow uses `grow`, shrink uses `shrink * flex_base_size`. Clamp tentative sizes to min/max, compute the total clamp violation, and freeze the items whose violation has the sign of that total (all unfrozen items when it is zero). Continue until all items are frozen. This is the only iterative sizing step in the capture.

After flexing, positive free space is offered to auto margins first, equally per auto-margin slot. Any remainder is placed by `justify_content`: `start`, `end`, `center`, `space-between`, `space-around`, or `space-evenly`, with their usual Flexbox main-axis meanings. When free space is negative, auto margins are zero and `justify_content` behaves as `start`. Physical left coordinates come from the resulting main axis, including `direction` and `row-reverse`.

A child group is then laid out recursively inside its assigned border box. Every node named in `probes` is reported with its physical left coordinate relative to the root border box and its assigned border-box width. Also report the number of flex lines in the root group. Convert those coordinates and widths to the same painted milli representation as `layout_model.md`, using the source case's DPR and half-up device-pixel rounding.
